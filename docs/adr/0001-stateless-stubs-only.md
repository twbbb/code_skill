# ADR 0001：外部下游只用无状态替身，不写假进程

- 日期：2026-10-24
- 状态：Accepted

被测服务调用的外部下游（微信、谷歌、邮件）在本机调不通，必须替代。wxtoken 最早写了一个有状态的假微信进程 `fakewx`：它记得自己发过哪个 token，旧 token 回 40001，还统计调用次数。

**决定：外部下游一律用 rpcproxy 缓存目录里的替身文件，trpc 下游和 HTTP 下游都一样，不再写假进程。替身没有状态，一份请求对应一份固定返回。用例需要下游前后返回不同时，让两次请求的缓存 key 不同，各自命中一份文件（比如 `access_token` 算进 key，旧 token 和新 token 各一份）；做不到时把用例拆成 `NNa`、`NNb`，两段之间换文件。调用次数从日志里 `rpcproxy cache|hit|<文件>` 的行数来数。**

为此 HTTP 版 rpcproxy 的缓存 key 只忽略 `timestamp`、`nonce`、`signature`，和 trpc 版一样，不按方法配置。

## Considered Options

- 有状态的用例写假进程，其余用替身：能模拟的行为更多，但每个外部下游都要维护一个小服务，还要有重置、查状态的控制接口；用例文档和执行脚本也要同时支持两套替代方式。
- 外部下游全用假进程：fakewx 证明了这条路可行，但每接一个新下游就得写一个。

## Consequences

- 一次调用里下游返回什么，完全由请求内容决定。被测代码如果对同一份请求在一次调用里调两次、并期望两次返回不同，这种用例测不了，只能在用例文档里写明不覆盖。
- 替身照接口文档手写，录不到真实返回，用例的「降级」行要写明这一点。
- 例外：被测服务本身是代理（如网关）时，要验证的就是「后端收到了什么」，无状态替身做不到。这时的回显后端（如 `gateway/testcase/echo/`）算测试夹具，归到兄弟服务一类，在本机真实起起来；它只回显收到的内容，不模拟任何外部系统的行为。
